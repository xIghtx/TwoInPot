# TWO IN POT 행사 버전

이 문서는 이전 항아리 캐릭터 버전의 기록이다. 현재 제작 방향과 조작은 [협동 등반 버전](ClimberEdition.md)을 참고한다.

## 현재 제작 범위

- 노트북 두 대, 각자 키보드 A/D 또는 방향키와 Space로 조작.
- 총 12개 스테이지. 각 스테이지는 역할별 기믹 연습 후 본 도전으로 전환한다.
- 전 코스 예상 시간은 15~25분을 설계 목표로 삼았다. 실제 어린이 플레이 시간은 아직 측정하지 않았다.
- 연습과 본 도전 사이에는 위치·장치·충전·타이머·릴레이 상태를 초기화한다.
- 게임패드, 유료 모델, 외부 에셋 다운로드 없이 구성한다.

| 번호 | 스테이지 | 함께 하는 일 |
|---|---|---|
| 01 | 첫 만남 | 로직이 스위치를 밟고 피지컬이 문을 통과한다. |
| 02 | 벡터 발사 | 로직이 A/D로 각도를 정하고 피지컬이 Space 충전 후 뗀다. |
| 03 | 이동 발판 | 로직이 발판을 옮기고 피지컬이 올라타서 건넌다. |
| 04 | 바람 터널 | 로직이 콘솔을 밟아 바람을 만들고 피지컬이 넓은 틈을 건넌다. |
| 05 | 자석 상자 | 로직이 상자를 옮기고 피지컬이 발판으로 사용한다. |
| 06 | 속도 게이트 | 로직이 문을 열고 피지컬이 달리는 속도로 통과한다. |
| 07 | 회전 다리 | 로직이 기울어진 다리 각도를 맞춘다. |
| 08 | 파트너 회로 | 로직이 스위치를 유지하는 동안 피지컬이 깃발에 도달한다. |
| 09 | 하늘 승강기 | D로 올리고 A로 내리는 승강기로 높은 테라스에 도달한다. |
| 10 | 똑딱 문 | 로직의 Space 입력마다 3.5초 열리는 문에 타이밍을 맞춘다. |
| 11 | 균형 친구 | 추와 다리의 움직임을 보면서 넓은 틈을 건넌다. |
| 12 | 다시 함께 | 첫 콘솔로 첫 문을 잠금 해제하고 두 번째 콘솔을 유지해 마지막 문을 연다. |

## 그래픽과 조작감

캐릭터는 실제 메시 에셋으로 만든 항아리 몸통, 손잡이, 입구 테두리, 눈과 발을 사용한다. 주황색 피지컬과 청록색 로직으로 구별한다. 외부 모델링 파일을 가져오는 방식이 아니라 Unity 에디터 생성기로 메시를 저장하며, Art/Models에서 수정할 수 있다.

점프 때 몸을 늘리고 착지 때 눌리는 동작, 이동 기울기와 발 움직임, 숨쉬기와 눈 깜빡임, 발사 충전 움츠림, 착지 먼지를 추가했다. 표현용 모델만 변형하고 네트워크 충돌체는 변형하지 않는다. 기존 1~8과 신규 9~12의 표면은 모서리를 깎은 메시로 통일하고 콘솔 눌림, 깃발 흔들림, 바람 흐름을 추가했다.

점프 입력 기억 시간은 0.12초, 발판을 벗어난 뒤 허용 시간은 0.10초다. 바람의 속도 성분은 기본 이동 계산과 별도로 유지하고, 서 있는 발판의 변위를 플레이어에 적용한다. 장치 조작 스테이지의 로직은 A/D를 장치 제어에 사용하며 제자리에서 조작한다.

## 실행 및 재생성

- Unity 6000.6.0f1에서 Assets/TwoInPot/Scenes/Prototype.unity를 연다.
- Windows 실행 파일은 Builds/Windows/TwoInPot.exe다. 두 노트북에는 Windows 폴더 전체를 같은 버전으로 복사한다.
- 이전 프로토타입 빌드는 이번 버전과 연결할 수 없도록 버전 식별자를 바꿨다.
- 재생성 메뉴: Two In Pot > Upgrade Festival Edition. 열린 씬에 저장하지 않은 변경이 있으면 먼저 저장해야 한다.
- 첫 갱신 전 씬과 플레이어 프리팹의 백업은 Docs/Backups/BeforeFestivalUpgrade에 보관한다.
- 프로토타입을 처음부터 재생성하는 기존 메뉴는 행사 버전 편집 용도가 아니다.

## 제작 완료 후 테스트

Editor.FestivalUpgrade.FinishAndVerify는 제작 갱신 후 12개 스테이지 참조와 플레이어 모델을 검사하고 프리뷰 및 Windows 개발 빌드를 만든다.

개발 빌드의 `-potHost -potFestivalTests`와 `-potClient -potFestivalTests`를 별도 프로세스로 실행하면 두 참가자의 역할 선택 RPC, 실제 입력 RPC 전달, 모든 스테이지의 연습 중 출구 차단·다시 시작·연습 완료·본 도전 전환·클리어, 점프/착지 물리, 점프 모델 변형, 승강기 탑승, 시간제 문 재닫힘, 마지막 릴레이, 전체 재시작, 참가자의 12단계 상태 수신을 검사한다. 일반 실행에서는 테스트가 동작하지 않는다.

이 테스트는 기믹 조건과 진행 상태의 회귀 검사이며, 일부 위치를 서버에서 지정한다. 어린이가 모든 구간을 직접 조작해 끝까지 통과하는 사용성 검사나 실제 학교 네트워크 두 노트북 검사를 대체하지 않는다. 실제 실행 결과는 Docs/Verification/FestivalResults.md에 기록한다.

## 사용자 검토 및 미구현 목록

현재 요청 중 사용자 승인이 필수라서 보류한 기능은 없다. 아래는 현 초안을 보고 추후 결정할 수 있는 사항이며, 아직 구현하지 않았다.

| 미구현 항목 | 결정할 내용 |
|---|---|
| 행사 코스 선택 메뉴와 강제 시간 제한 | 12개 전체 코스만 쓸지, 대기줄에 따라 짧은 코스도 제공할지 |
| 확정 아트 콘셉트에 맞춘 별도 모델 교체 | 현재 제작한 항아리 모델을 최종 디자인으로 쓸지, 다른 캐릭터로 바꿀지 |

음악·효과음·저장 기능은 이번 요청에 포함해 구현하지 않았다. 난이도와 예상 플레이 시간은 어린이 플레이 검토 후 확정해야 한다.
