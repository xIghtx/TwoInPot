# 수신 메모와 일반 엔딩 — 2026-10-28

## 화면과 규칙

- 본 도전에서만 자신의 수신 메모 한 장을 표시한다. 다른 사람에게도 메모가 있다는 문구, 상대 진행도, 순위, 비교 점수, 승자 표시는 없다.
- 주황색은 접힌 메모, 파란색은 업무 지시를 받는다. 주황색은 이동 흔적과 망치 동작, 파란색은 장치 점검을 수행한다. 두 역할은 방마다 서로 다른 요청을 받는다.
- 본인의 성공 기록과 진행도는 호스트가 판정하고 해당 플레이어에게만 전송한다. 호스트는 서버이므로 기술적으로 양쪽 상태를 갖지만 호스트 화면도 자기 메모만 표시한다.
- 실패해도 공동 진행을 막거나 점수를 깎지 않는다. 연습 행동은 집계하지 않는다. 재시도는 완료 기록을 유지하며 같은 방에서 여러 번 성공해도 한 번만 센다. 처음부터 다시하기와 새 세션에서는 초기화한다.
- 성공률은 전체 12개 메모 기준. 0~3개, 4~7개, 8~12개로 일반 엔딩의 개인 후일담을 나눈다. 같은 문으로 나가지만 각 노트북의 후일담이 다를 수 있다. 분기 기준과 상대 기록은 화면에 표시하지 않는다.
- 기존 3·6·9·12의 네 선택 기록을 복원하고 최종 협동 게이트를 통과하는 트루 엔딩 조건과 원문은 그대로 유지한다. 트루 엔딩은 메모 성공률보다 우선한다.

## 스토리 보강

방마다 입실자 이름의 빈칸 → 반복 도색 → 반환되지 않은 이름표 → 퇴실자 수와 이름 수의 불일치 → 반복되는 파란 서명 → 닳은 삭제 버튼 순서로 단서를 놓는다. 개인 메모도 초반의 단순 요청에서 후반의 '빈칸으로 두지 말아 줘'와 '마지막 확인란'으로 변한다. 파란 인물이 운영자이며 의도적으로 기록을 지웠다는 설정은 유지한다. 이유는 아직 단정하지 않는다.

일반 엔딩의 개인 후일담:
- 주황: 빈 봉투 / 남은 자국 / 돌아올 자리.
- 파랑: 미확인 인계 / 접힌 인계서 / 남겨 둔 인계서.
- 트루: 기존 남겨 둔 이름.

## 검증과 남은 검토

빌드와 숨김 두 프로세스 회귀 검사를 통과했다. 호스트 1,039회, 참가자 1,321회 검사(반복 UI 확인 포함), 양쪽 종료 코드 0. 12개 방의 역할별 요청 구분, 4개·8개 성공 경계, 실제 망치 밀기와 게이트 유지의 메모 판정, 연습 제외, 재시도 유지, 전체 초기화, 참가자에게 상대 진행도 미전송, 본인 지시문 표시와 UI 배치, 기존 12스테이지·네 기록·일반/트루 엔딩을 검사했다. 24개 요청을 모두 사람이 조작해 달성한 검증은 아니다.

로그: Verification/PrivateNotesBuild2.log, PrivateNotesHost2.log, PrivateNotesGuest2.log. 첫 검사는 메모를 표시한 첫 프레임의 배치 계산을 기다리지 않아 중단되어, 배치 완료를 플레이 중 확인하는 방식으로 고친 뒤 재검사했다. 참가자 종료에 따라 호스트 조작 검사도 함께 실패했던 첫 실행 로그는 보존했다.

같은 PC에서 두 실행 파일의 평균은 58.4/58.5fps. 1% 하위는 22.4/22.8fps, 최악 프레임은 113.6/98.7ms로 순간 지연이 있었다. 최소 30fps 유지나 다른 노트북의 성능을 보장하는 결과가 아니다. 기존 종료 시 ComputeBuffer 정리 경고와 참가자 시작 시 Curl 출력 오류는 남아 있지만 연결·기능 검사는 통과했다.

실제 어린이의 메모 발견률, 행동 난이도, 역할별 성공률 균형과 두 노트북에서의 반응은 현장 검토가 필요하다. 성공률 분기는 실제 사람이 플레이해 밸런스를 확인한 결과가 아니라 이번 구현의 초깃값이다. 두 기기로 복사할 때는 양쪽 모두 최신 Builds/Windows 폴더 전체를 사용해야 한다(프로토콜 private-notes:5).
