# 행사 버전 제작 및 검증 결과

이 결과는 이전 항아리 캐릭터 빌드의 기록이다. 이후 사람형 등반가와 기술자로 바꾼 빌드의 결과는 [ClimberResults.md](ClimberResults.md)에 기록한다.

## 제작 결과

- 8개에서 12개 스테이지로 확장했다. 9~12는 승강기, 시간제 문, 균형 다리, 두 단계 릴레이다.
- 기존 1~8에도 입체 표면과 콘솔·깃발·바람 반응을 적용했다. 3~7의 틈·높이·회전축을 조정했다.
- 항아리 몸통·손잡이·테두리·눈·발을 실제 메시 에셋으로 제작했다.
- 점프 늘어남, 착지 눌림과 먼지, 이동 기울기와 발 움직임, 숨쉬기, 눈 깜빡임, 충전 움츠림을 구현했다.
- 점프 입력 기억 0.12초, 발판 이탈 허용 0.10초, 이동 가감속, 발판 탑승 이동, 별도 바람 속도를 적용했다.
- 12개 모두 기믹 연습 후 본 도전을 시작한다. 실제 점프·발사·장치 변화로 연습을 판정한다.

## 추가 동작 및 예외 검사

- 두 프로세스의 접속, 소유 플레이어 확인, 역할 선택/수락 RPC와 게임 시작.
- 참가자의 실제 입력 RPC가 서버에 전달되는지 확인.
- 실제 점프 상승과 착지, 점프 중 메시 변형.
- 착지 직전 입력한 점프를 기억해 실행하는지 확인.
- 공중에서 Space를 떼기만 해서는 발사 연습이 완료되지 않는지 확인.
- 승강기의 가장 낮은 위치에서 더 내리는 입력만 해서는 연습이 완료되지 않는지 확인.
- 바람이 기본 이동 계산에 덮이지 않고 플레이어를 이동시키는지 확인.
- 승강기가 탑승한 플레이어를 위로 운반하는지 확인.
- 시간제 문 열림, 3.5초 뒤 닫힘, 다시 열기와 통과.
- 마지막 출구의 조기 완료 차단, 첫 릴레이 문 유지, 두 번째 콘솔과 최종 완료.
- 마지막 스테이지에서 완료 상태 유지, 처음부터 다시 할 때 진행·연습·릴레이 초기화.
- 참가자 UI의 연습 카드 표시와 서버 연습 단계의 일치.

그래픽 호스트 실행 시작 부분에 `Curl error 23: Failure writing output to destination, passed 293 returned 0` 진단이 한 번 기록됐다. 호출 원인은 로그에서 특정되지 않았다. 그 뒤 로컬 네트워크 연결 및 모든 게임 검사는 통과했다. 이 진단을 해결한 것으로 간주하지 않는다.

## 검증 범위의 한계

두 게임 프로세스를 같은 컴퓨터에서 로컬 UDP로 연결했다. 일부 검사는 서버에서 플레이어 위치와 입력을 지정해 진행 조건을 재현했다. 이는 어린이가 모든 구간을 키보드로 직접 조작해 완주했다는 의미가 아니다.

아직 수행하지 않은 항목은 실제 노트북 두 대에서 학교 네트워크로 연결하기, 인터넷 방 코드/Relay 접속, 실제 어린이의 완주 시간·난이도·가독성 확인이다. 전 코스 15~25분은 설계 목표이며 측정 결과가 아니다.

사용자 검토를 위한 미구현 항목은 [행사 버전 문서](../FestivalEdition.md)의 마지막 목록에 정리했다. 요청 범위 중 필수 승인 대기 때문에 보류한 기능은 없다.
