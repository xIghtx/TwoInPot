# 연결 환경 및 현재 빌드 검증

검증일: 2026-10-28. 사용자에게 두 번째 노트북이 없어 **한 PC에서 호스트와 참가자 두 프로세스**로 검사했다. 게임 창 조작·포커스 전환·네트워크 설정 변경은 하지 않았다.

## 현재 환경

| 항목 | 관찰 결과 |
| --- | --- |
| 연결 장치 | Intel Wi-Fi 6E AX211, Wi-Fi 연결 중 |
| 현재 IPv4 | `192.168.219.100` |
| 기본 공유기 | `192.168.219.1` |
| 네트워크 프로필 | Public, Internet 연결 상태 |
| 무선 링크 속도 | 325Mbps — 인터넷 속도 측정값은 아님 |
| 공유기 ICMP 응답 | 2회 성공, 3ms / 6ms |
| 게임 전송 | UDP 7777 |
| 호스트 수신 주소 | `0.0.0.0:7777`, 실제 UDP 엔드포인트 관찰 |
| 게임 방화벽 규칙 | Public 수신 TCP·UDP Allow 규칙 활성화 |

처음 읽은 방화벽 Action 숫자를 잘못 해석해 차단으로 설명했으나, enum의 문자열을 다시 읽어 **Allow**임을 확인했다. 방화벽·프로필·공유기 설정은 변경하지 않았다. 허용 규칙이 존재한다는 사실만으로 다른 장치에서의 실제 접속까지 검증한 것은 아니다.

## 실행 결과

| 검사 주소 | 호스트 확인 | 참가자 확인 | 종료 코드 |
| --- | ---: | ---: | --- |
| `127.0.0.1:7777` | 1,014개 통과 | 611개 통과 | 양쪽 0 |
| `192.168.219.100:7777` | 1,014개 통과 | 607개 통과 | 양쪽 0 |

확인 개수에는 반복 UI·렌더러 확인이 포함되므로 참가자 수치는 실행 시간에 따라 달라진다. 고유 시나리오가 해당 숫자만큼 있다는 뜻은 아니다.

두 실행 모두 다음을 포함한다.

- 연결·서로 다른 역할 선택·양쪽 수락·플레이 시작·정상 종료.
- 12개 스테이지의 연습·리셋·본 도전·클리어 및 망치·바람·승강기·시간제 문·릴레이 동작.
- 선택 기록 동기화, 한 사람만으로 복원 불가, 연습 중 복원 불가, 재시도 유지, 처음부터 재시작 시 초기화.
- 일반 엔딩과 트루 엔딩 및 참가자 동기화.
- 복원한 문장 다시 읽기, 번호식 수집 안내 제거.
- 9개 효과음의 실제 PCM 데이터·모노 채널·짧은 길이·음량 여유·감쇠 끝부분, 음소거·재생 재개.
- GPU 장면 렌더링·픽셀 프레임·640×360 내부 화면.

## 성능

같은 PC에서 두 프로세스 동시 실행, 출력 설정 1280×720, 내부 640×360. 개발 검사에서 매 프레임 카메라를 강제로 렌더링해 숨긴 창의 렌더 생략을 피했다. 시작 5초와 로비는 통계에서 제외한다.

| 주소 | 호스트 평균 / 느린 1% 평균 | 참가자 평균 / 느린 1% 평균 | 최악 프레임: 호스트 / 참가자 |
| --- | --- | --- | --- |
| 루프백 | 60.0 / 57.2fps | 60.0 / 57.7fps | 23.4 / 30.5ms |
| 자체 Wi-Fi IPv4 | 60.0 / 56.5fps | 60.0 / 57.6fps | 32.3 / 29.5ms |

두 실행 모두 33.33ms 초과 프레임은 0회였다. 이번 측정 구간에서 30fps 목표를 충족했다. 앞선 2026-10-27 실행에서는 같은 PC에서 순간 지연이 관찰됐으므로, 모든 부하 상태에서 항상 같은 최저 프레임이 나온다고 보장하지 않는다.

## 검사 범위의 한계

- 자체 IPv4로의 접속도 **같은 PC 내부**에서 처리된다. 다른 노트북, 무선 구간의 실제 게임 패킷 전달, 공유기의 장치 간 격리·지연·패킷 손실은 미검증이다.
- 인터넷 방 코드/Relay 접속은 이번 검사에 포함하지 않았다.
- 한 PC에서 키보드 한 개로 두 역할을 동시에 직접 플레이한 검사가 아니다. 개발 검사 입력과 위치 제어를 사용했다. 실제 어린이의 난이도·플레이 시간·발견률은 미검증이다.
- 행사장 스피커에서의 실제 효과음 음량은 미확인이다.
- Unity 종료 때 기존 ComputeBuffer 해제 경고가 남는다. 검사 중 예외나 실패는 없었다.

## 재현과 근거

접속 주소 지정은 개발 검사 옵션 `-potAddress <IPv4>`로 추가했다. 생략하면 기존 `127.0.0.1`을 사용한다. 일반 게임의 메뉴·입력·접속 동작은 바꾸지 않았다.

- `NetworkEnvironment.json`: 환경과 방화벽 관찰값. UDP 엔드포인트 목록이 비어 있으면 스냅샷 시점에 검사가 이미 종료된 상태다.
- `NetworkLoopbackHost.log`, `NetworkLoopbackGuest.log`: 루프백 통합 검사.
- `NetworkIPv4Host.log`, `NetworkIPv4Guest.log`: 실제 지정 주소·통합 검사·성능.
- `NetworkAddressBuild.log`: 주소 지정 옵션을 반영한 Windows 빌드 성공.

실행 파일은 `Builds/Windows/TwoInPot.exe`이며 다른 PC에는 **Windows 폴더 전체**를 같은 버전으로 복사해야 한다. 이 PC에서 두 개를 열어 직접 접속할 때는 호스트를 하나만 만들고 다른 실행 파일에서 `127.0.0.1`로 참가한다. 현재 Wi-Fi IPv4는 다른 네트워크나 DHCP 갱신 때 달라질 수 있다.
